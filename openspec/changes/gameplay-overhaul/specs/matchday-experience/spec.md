# Matchday Experience Specification

## Purpose

Turns the instant inline match simulation into a deterministic 0–90 match replay with a minute-ordered event timeline, a scorecard with scorers and minutes, a dashboard push-to-match flow, post-match return to the dashboard, and an in-app alert banner when a match is playable.

## Requirements

### Requirement: Playable match sequence

The system MUST run a playable 0–90 match sequence whose total real-time duration SHALL be approximately 4.5 minutes (2 minutes first half, 2 minutes second half, 30 seconds stoppage time).

#### Scenario: Full match plays start to finish

- GIVEN the user taps "Jugar" for a pending fixture with sufficient energy
- WHEN the match sequence starts
- THEN the sequence advances from minute 0 to 90 in the configured real-time budget

#### Scenario: User backgrounds the app mid-match

- GIVEN a match sequence is playing
- WHEN the app is backgrounded or the screen loses focus
- THEN the sequence SHALL pause safely without corrupting the timeline or result

### Requirement: Deterministic event timeline

The system MUST derive the match from a single minute-ordered event timeline generated by the simulation, covering goal, foul, yellow card, red card, injury, and penalty events. Each goal event MUST record the scorer and the fictional minute.

#### Scenario: Events appear at scheduled minutes

- GIVEN a generated timeline contains a goal at minute 67 by the player
- WHEN the replay clock reaches minute 67
- THEN the goal event SHALL be rendered with scorer and minute

#### Scenario: Timeline is stable across render passes

- GIVEN the same match inputs
- WHEN the timeline is generated more than once
- THEN the event sequence and final score SHALL be identical

### Requirement: Scorecard result

The system MUST present, after the final whistle, the final score, the winner or draw, and each goal with its scorer and minute for both teams.

#### Scenario: Result with scorers

- GIVEN the match ended 3–1
- WHEN the sequence finishes
- THEN the scorecard SHALL list the 3 home goals and 1 away goal with scorer and minute

### Requirement: Post-match return to dashboard

The system MUST return the user to the dashboard after the result screen; it MUST NOT land on the menu or new-career screens.

#### Scenario: Return after result

- GIVEN the user completed a match
- WHEN the result is confirmed
- THEN the user lands on the dashboard with the match recorded

### Requirement: Dashboard starts the match

The dashboard "Jugar" action MUST open the match overlay instead of simulating inline.

#### Scenario: Tap Jugar opens overlay

- GIVEN a playable fixture on the dashboard
- WHEN the user taps "Jugar"
- THEN the match overlay opens and the sequence starts

### Requirement: In-app match-day alert

The system MUST show an in-app banner when a fixture is playable, and MUST NOT use system notifications.

#### Scenario: Playable fixture shows banner

- GIVEN the next fixture is playable
- WHEN the user lands on the dashboard
- THEN a banner with a play action SHALL be visible

#### Scenario: No playable fixture hides banner

- GIVEN no fixture is playable or energy is insufficient
- WHEN the dashboard renders
- THEN no banner SHALL be shown

### Requirement: Suspension carry-over preserved

Existing behavior SHALL be preserved: a red card or injury sustained in the replayed match MUST mark the next fixture as non-playable.

#### Scenario: Red card suspends next match

- GIVEN the player received a red card
- WHEN the match ends
- THEN the next fixture SHALL be shown as suspended
